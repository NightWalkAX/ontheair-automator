    Catalog Editor

    Browse this channel like a file system: Show type ▸ Show ▸ Season ▸ episodes on the left (how the scheduler sees it), the real on-disk folders on the right (the Library). Drag a folder or clip from the Library onto a show to organize it — you'll be asked which season the clips belong to (blank keeps the seasons read from S02E..-style names), or drop onto a season folder to skip the question. If a whole "show" turns out to be just one season of another, open it and use Merge into show… to fold it in. Select clips with the checkboxes to bulk-edit. Nothing airs until you approve it. Non-destructive: files on disk are never moved or renamed.

    Air Spec · normalise the library with ffmpeg

    Brings every clip to one house format so OnTheAir Video plays the whole catalogue with the same timing and no audio drift. Each clip is converted to a work file, verified, then swapped in — the original is moved to the archive folder, never deleted. This routine is slow on purpose: it re-encodes at broadcast quality over the share, one clip at a time. Expect hours for a channel and days for the whole library. Start it, walk away, and come back to this tab — the queue lives in the database, so it survives a reload and picks up where it stopped after a restart.

    A converted clip changes name (an .avi becomes a .mov), so days already pushed to OTAV are repaired for you: the clip is re-pointed in place on the playout Mac, keeping its slot, its name and its watermark — or, when the new file's runtime moved enough to change the block's fit, that day is pushed again. Nothing is moved until every affected day has been checked, and the original is archived only once those playlists name the new file, so no playlist is ever left naming a file that isn't there. The clip on air, one about to start, and today's playlist as a whole are never rebuilt automatically.

    ⚙︎ Change the house spec

    Every clip is measured against this and converted to it. Changing it re-judges the queue: clips that were on spec may no longer be, and anything already converted is queued again. Clips already swapped in need the library probed again — their stored shape describes the file that went to the archive, not the one now in its place.

      Signal Monitor · watch the public feeds, e-mail when one goes black

      Each feed is read in the background, with nobody watching: ffmpeg takes one small frame per second from the lowest-quality version of the stream, and the app checks how much of the picture is lit. For a feed linked to an OTAV channel, the app first tries a resync of that channel and only alerts if the picture doesn't come back. The sound is followed the same way, on its own. When a feed stays black or silent longer than the limit, or stops sending anything (no signal), whoever is on shift gets an e-mail, and another when it comes back. If the shift roster has nobody for that time, the e-mail goes to the whole list instead. Alerts that happen within a few seconds of each other go out as one message. If a feed is linked to a channel, the e-mail also says which clip OTAV had on air.

      ✉️ Who gets the alerts

      Use an app password, not the account password: Google account → Security → 2-Step Verification → App passwords. Leave it empty to keep the one already saved.

      ⚙︎ When to raise an alert

      The public feed runs about 30–40 s behind the playout, so the wait can't be much shorter than a minute. If the resync is refused (OTAV unreachable, or its API user is below access level 3) the alert goes out at once.

      Analog channel · Leightronix UltraNEXUS-HD

      The analog channel is scheduled like every other channel — templates, blocks, approval and Push to Air on the Schedule tab. What differs is the device: it keeps one week (Sun–Sat) that repeats, so pushing a date replaces that weekday, and only today to six days ahead can be pushed. Each block starts at its own time, and whatever a block leaves before the next one is filled with the device's Program Guide. Clips play from the device's own disk, so files have to be uploaded before a push can use them. Every publish backs the device up first, and any backup can be put back on air below.

      …
      The analog channel has no address or API key yet. Set its IP, port and API key under Channels & Templates → edit on the Analog row, and switch it on.
